# AGENTS.md: Rheoson V3

> Read this before changing anything. Keep it accurate when the layout changes.
> Product spec: [docs/PRD.md](docs/PRD.md) · Architecture: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) · Design: [docs/DESIGN.md](docs/DESIGN.md) · Work plan: [docs/ROADMAP.md](docs/ROADMAP.md)

Rheoson V3 is a TypeScript monorepo: a Vite + React single-page app, a Hono API on Cloudflare Workers, Neon PostgreSQL through Drizzle, and music delivered by external providers rather than hosted by us.

## Where this branch sits

`development` is cut from `main` at `3d48e63`. `main` still runs V2 (FastAPI, Mongo, yt-dlp) and is not touched from here. V3 is built on this branch from `v3.0.0` forward, promoted to `dev` for review at `v3.9.0`, and to `main` at `v3.10.0`. V2 is history, not a folder in this tree: read it with `git show main:<path>` for a decision, never import or copy it.

## Layout

```
web/                          Vite + React SPA (no SSR), static assets on Vercel
web/src/components/<domain>/  one component per file, domain being ui, layout, player, home, music, feedback, auth
web/src/pages/                one route surface per file
web/src/hooks/                a hook only when a second component needs it
web/src/lib/                  client-side logic, one concern per file
api/                          Hono on Workers, /api/v1
api/src/routes/               one router per resource; validation and response shape only
api/src/services/             the business decision; the only layer that composes repositories
api/src/repositories/         Drizzle queries, one file per table group
api/src/providers/           provider adapters behind one interface, one file each
api/src/db/                   schema and the Neon client; migrations live in api/drizzle/
api/src/middleware/           cross-cutting request work
packages/shared/              zod contracts, response envelope, error codes, track identity
docs/                         PRD, ARCHITECTURE, DESIGN, ROADMAP
skills/                       installed agent skills, locked in skills-lock.json
.github/workflows/            the gates every push runs
```

## Names

No hyphens in a path. A file, a folder, an export and a migration follow one shape: camelCase for modules (`requestContext.ts`, `rateLimit.ts`), PascalCase for a component's export (`playerBar.tsx` exports `PlayerBar`), uppercase for a doc (`ROADMAP.md`). A two-word folder is camelCase too (`components/nowPlaying/`, `lib/audioEngine/`).

| Kind | Convention |
| --- | --- |
| Web component | `web/src/components/<domain>/<name>.tsx`, export `<Name>` |
| Web hook | `use<Name>.ts` beside the component that owns it |
| Web page | `web/src/pages/<name>Page.tsx`, export `<Name>Page` |
| Web helper | `web/src/lib/<concern>.ts`, or `lib/<area>/<concern>.ts` where an area exists (`lib/api`, `lib/auth`) |
| API route | `api/src/routes/<resource>.ts`, export `<resource>Routes` |
| API service | `api/src/services/<domain>.ts` |
| API repository | `api/src/repositories/<tableGroup>.ts` |
| API middleware | `api/src/middleware/<concern>.ts` |
| API provider | `api/src/providers/<name>.ts`, export `create<Name>Provider` |
| Shared contract | `packages/shared/src/<topic>.ts`, re-exported from `index.ts` |
| Migration | generated by `pnpm db:generate`; never hand-named |

Imports: `@/` inside `web/src`, relative paths inside every other package, and never a climb above `../../`.

## Branches and tags

`development` is where every commit lands. `dev` is review and testing, reached by a pull request. `main` is production, reached from `dev` by a pull request the owner merges. Nothing goes to `dev` or `main` directly. The exact system is Vstore's and lives in [GIT_WORKFLOW.md](GIT_WORKFLOW.md).

- **Commit** = Conventional Commits with a scope: `feat(api): return 404 when the playlist is gone`. The subject states the change, the body says why and what was verified.
- **Tag** = one annotated tag per verified commit, `v3.[phase].[step]`, annotation `v3.0.3: <what landed>` plus what was verified. Numbering is Vstore's, unchanged.
- **Phase** = a coherent chunk of the product, closed by a pull request titled `v3.P — <theme>`.
- Next number is the highest existing plus one. A step that was never cut is never backfilled.
- A tag is cut only when typecheck, lint and build pass and the behaviour is verified. Never move or delete a published tag.

## Non-negotiables

- **No attribution.** No `Co-Authored-By`, no "Generated with", no agent names in commits, tags, docs or comments.
- **No `------*` horizontal rules** in docs or comments.
- **No kebab-case paths.** `playerBar.tsx`, never `player-bar.tsx`.
- **@/ alias** for `web/src`, never relative climbs past one level.
- **One source of truth for shapes.** A response shape is a zod schema in `packages/shared`; the API parses it and the client parses it. Never hand-write a type that mirrors a schema.
- **Errors carry codes.** Every failure goes through the shared error registry, and the response envelope always has the same shape.
- **Semantic tokens only.** Components read `--background`, `--foreground`, `--muted-foreground`, `--primary`, `--color-brand`; never a raw Tailwind palette colour and never a hex value.
- **No persisted provider URLs.** Provider stream and preview URLs are signed and short-lived; resolve at play time, store the provider id.
- **Server decides auth.** The API verifies the Clerk session on every request; the client never sends a user id it chose.
- **Two origins, one base URL.** The web app ships on Vercel and the API on Workers, so the client reaches the API through `VITE_API_BASE_URL` (`/api/v1` in development, through the Vite proxy). Nothing hardcodes a host.
- **Routes call services.** A router validates, calls a service and shapes a response; the decision lives in the service and the query in the repository. A route that imports a repository has skipped a layer.
- **The app works without a database.** `hasDatabase()` decides, not a crash: accounts answer from the token, saving stays local, and a deployment missing a secret still serves every screen.

## Verification

Before a commit that touches the web app: `pnpm typecheck`, `pnpm lint`, `pnpm --filter web build`. For the API: `pnpm --filter api typecheck` and `pnpm --filter api exec wrangler deploy --dry-run` when the worker config changed. CI runs the same gates on every push.

## Constraints worth remembering

- Cloudflare Workers Free gives 10 ms CPU per request, so no password hashing and no SSR in the Worker. Auth is Clerk; the app is a static-asset SPA.
- 20 users by design: build for correctness and taste, not for quota.
- Two origins means CORS is an exact allowlist and auth is a bearer token. There is no cookie to share between hosts.
- A skill in `skills/` is reference material, not a dependency. Read it, apply the decision, delete nothing from it.
